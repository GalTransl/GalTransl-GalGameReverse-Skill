# KAG 文本：nm / np / exlink 方言

入口：[kirikiri_kag_extract.py](../../python/engines/kirikiri_kag_extract.py)；语义层：[kirikiri_kag_text.py](../../python/engines/kirikiri_kag_text.py)。仅用于符合下述宏语义的 KAG 文本，PSB/SCN 走 [引擎页](../kirikiri.md) 的对应入口。

## 适用条件

| 项目 | 规则 |
|---|---|
| 编码 | UTF-8 或 UTF-16LE/BE BOM；保留编码、BOM 和换行，无 BOM/CP932 不自动猜测 |
| 姓名与分页 | `@nm t="显示姓名"` 设置姓名，`[np]` 结束一页并清名；姓名不跨页继承 |
| 正文 | 多行合成一条 message，物理换行映射为 JSON `\n`；保留 `[r]` 及已知行内控制 |
| 选项 | 只写 `@exlink txt="选项"` 的 txt，不改 target、voice、exp 等属性 |
| ruby | `[漢字'よみ]` 的基底可译，注音与顺序保留；`[・]` 为保护标记 |
| 非目标内容 | 命令行、标签、脚本块、宏定义和注释不导出；对白注释按原物理行插回 |

先核对宏定义，同名宏不保证同义。动态属性和未知行内语法拒绝；系统 UI、动态生成文本及其他方言需单独适配。

## 宏重定义的方言：文本框架由 first.ks 决定

上表的 `@nm` / `[np]` 只是**一种**宏方言。KAG 允许游戏在 `first.ks` 里用 `[macro]` **重定义换行与分页语义**，
因此**「哪些命令真正换页」必须以该游戏自己的宏定义为准**，不能按标签名推断。

典型差异（同一批标签，语义完全不同）：

| 标签 | 一种方言 | 经宏重定义后 |
|---|---|---|
| `[r]` / `@r` | 换行 | 可能仍是行内换行，或**被游戏重新定义成别的动作** |
| `[p]` / `[page]` | 换页 | 换页（通常稳定） |
| 自定义宏（如 `@pp` / `@i` / `@ir`） | 不存在 | 由 `first.ks` 的 `[macro]` 展开，可能才是**真正的换页点** |

后果：若按"通用 KAG 语义"把 `@r` 当换页切开，
在**把换页交给自定义宏**的游戏里，"同一文本框内的多句话"会被错误拆成多条 message。
⇒ **提取前必须先读 `first.ks` 的 `[macro]` 定义**，按该游戏的实际语义划分文本框。

### 以「文本框」为单位提取与回填

当换行/分页被宏重定义后，稳定的提取单位不是"行"而是**文本框**：

1. **先确定框边界**：由①该游戏的换页命令（含自定义宏）与②章节标签行共同决定；
   另有文件**不使用任何显式换页标记，而靠空行分段** —— 这类文件必须单独判定，
   不能沿用"有显式标记"的文件规则（否则整篇会塌成 1 个框）。
2. **框内多行合成一条 message**，行内换行标记保留为可还原的分隔；译文可自由重排断行。
3. **说话人单独成字段**：说话人通常以"独立一行"表示。
   判定需要**双条件**（是短称谓 **且** 本框内其后仍有正文），
   否则单行的拟声/旁白会被误判成人名。
4. **选项文字单独处理**：选项整行常以控制字符开头而被"文本行判定"排除，
   必须**单独提取**；回填时只替换可见文字，**属性（跳转目标、资源名）绝不能动**。
5. **章节标题与标签名分家**：`*标签|标题` 中 `|` 之后是**存档界面显示的标题**，
   可以翻译；`|` 之前的**标签名被跳转引用，绝不能改**。

### 质检口径（回填后必做）

- ⚠️ **"用原文回填再重提取"这一步的自洽性不能证明提取正确**：
  当源编码读错、或按错方言切分时，重提取可能与回填结果"一致地错"，
  该检验照样通过。它只证明**往返无损**，不证明**语义正确**。
- **正确的回填质检是行级重建比对**：把每个框的物理文本行摊平后逐行比对，
  绕开"说话人/正文如何切分"带来的歧义（同一批物理行按不同方式切成 `name` + 正文，
  在引擎里显示等价，但会让基于字段的比对报出大量假错位）。
- **提取正确性靠外部基线**：框数应与该游戏换页标记的出现次数量级相符；
  源文件与产物做双向差集；检查只出现一次的名字是否合理。
- **静态核验跳转链**：建立"文件 → 标签集合"映射，扫描全部跳转引用的 `storage` + `target`
  逐个解析，确认章节切换不会断。核验时**必须排除注释行**，
  否则会得到大量假阳性；"未解析"的引用要先与**原版解包**对照，
  原版自带的悬空引用不属于汉化引入的问题。
- 使用 `grep` 检索 CP932 脚本时要注意其把非 ASCII 文件当二进制处理，
  检索日文应改用能显式指定编码的读取方式。

> 本页只说明**方法**：哪些语义要核对、以什么为单位切分、如何验证。
> 具体命令与字段以实现和样本为准。


## 提取与打包

先确认索引、过滤器和成员范围。当前入口拒绝跨归档同路径覆盖与平铺 JSON 重名；需要先明确选择有效来源。

```text
python -m python.engines.kirikiri_kag_extract extract "游戏目录" "新的提取目录" --archives data.bin arc/extra.xp3 --members "scenario/*.ks" "01*.ks" --filter-spec "过滤器.json"
python -m python.engines.kirikiri_kag_extract pack "提取目录" "新的打包目录"
python -m python.engines.kirikiri_kag_extract pack "提取目录" "新的扁平补丁目录" --flat
```

提取生成 `gt_input/gt_output/original/metadata/reports`、原文 roundtrip 和中文前缀 smoke-test；后者不是正式译文。回填校验源哈希、原文与 manifest、条数、姓名、控制码、ruby 和换行，重读脚本并比较非文本结构，再按原过滤器封包、逐成员读回。缺少译文的成员保持原样。

| 打包方式 | 输出 |
|---|---|
| 默认 | 保留原成员目录的 `scenario.xp3` |
| `--flat` | 根目录成员的 `patch.xp3` |

两者均为脚本专用包，不能覆盖含系统/媒体的完整原包。`--flat` 只改变路径，不表示只包含变化成员；补丁挂载、已有补丁优先级与增量筛选按 [通用工作流](workflow.md#译文回注优先使用-patchxp3-增量补丁) 处理。

译文按同名放回 `gt_output` 后由 agent 回写。缺字时检查实际字体和归档资源；普通 TTF 不能仅改名当作 TFT。
