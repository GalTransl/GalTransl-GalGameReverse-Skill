# Malie / EXEC 外壳、控制 token 与引用升级

[工程资料](../../provenance/translation-engineering-notes.json)补充 UTF-16 EXEC 方言研究；没有新增 Camellia、PE writer、消息语义提取或 CODE/常量池重布局实现。已有[Malie API](../malie.md)只处理页内三种明确明文 fmt，不能由本页线索扩大支持。密钥、EXE 地址和游戏语音前缀表不随包保留。

## 外壳与 PE 资源

记录链为 EXEC bytes -> Camellia-128 ECB 解密 -> zlib -> UTF-16LE 字节码。该 ECB 方言与其他 Malie 偏移相关加密分开；显式从合法输入确认 key、块边界、尾填充和压缩大小，不能按某个 zlib 头如 78 9C 判断全部数据。确定性密码不代表重新 zlib 压缩后密文必然 bit-perfect。

EXEC 可能为松散文件，也可能位于 PE 自定义资源 type/name EXEC；静态定位资源，核对 ID/名称、语言项、RVA->文件映射和完整跨度，不加载 DLL/EXE。若有明确需求写 PE，需重建资源目录/数据及节容量、alignment、SizeOfImage、目录大小和适用校验，保留其他资源及 overlay。文件签名/加载条件另行检查；本 Skill 尚无该 writer，不把替换资源 bytes 当完整重建。

## 明文分区与地址单位

备忘录称“六段”，实际列出编号0到6的七个逻辑部分；按结构角色识别，不把数量描述当文件头字段。

| 逻辑部分 | 记录线索与约束 |
|---|---|
| IdentScope | 标识符名、VarType 链及附加字段；不同 fmt 的 count/链头不同 |
| 函数表 | 名称、函数 ID 和附加元数据 |
| 标签表 | 名称与指向 CODE 的入口 type，后者不能当普通类型号 |
| 常量池 seg3 | u32 字节长度、NUL 分隔 UTF-16LE；含文字、资源及身份字段 |
| CODE seg4 | u32 字节长度与变长指令 |
| 消息池 seg5 | u32 字节长度及带控制的 UTF-16LE 消息 |
| 消息表 seg6 | 消息计数及 seg5 内字节起点；末消息到池尾，不能越界读 i+1 |

String 长度的高位 `0x80000000` 是标志，剥去后按字节取实际长度并核对终止；VarType 链需限深/限数，具体 tag 参数和每个 fmt 的尾部以 parser 定义为准。未知头/链不得套某个样本字段数量。

## 代码与常量池引用

以下 opcode 为来源的**十进制编号**，需要匹配当前 VM 后使用：0/1/2 的 u32 CODE 目标；3 的 u32 funcid+u8 argc；4 的两个 u8 调用参数；45 的 u32 标签**索引**；49 的 u32 帧大小；51 的 u8 返回参数。尤其 51 若漏读 u8 会连锁错位，先回查前一条宽度，不把后续字节当新增 opcode。完整其他指令语义仍须定义，不把来源 default NOP 泛化为未知指令零宽。

9/10/12 记录为 u8/u16/u32 的 seg3 **字节偏移**引用；先验证目标为有效字符串起点，不因为同值恰好落入池中就判断任意立即数为 strref。改 seg3 须重映射每个已证明引用，宽度溢出时只有确认等价 opcode 后才可升级窄引用。升级改变指令长度，需重新布局全部 CODE 跳转、标签入口和受影响表，迭代至布局稳定；不能只修 pool offset。

仅改 seg5 时，独立消息索引可能允许 CODE 不动，但要确认消息结构与全部消费者。常量池中的资源名、语音标记、变量和显示姓名分开分类，语音前缀不能猜固定姓名；用户提供且经证实的角色对应关系可作只读上下文。

## UTF-16 控制 token

记录方言用 code unit `0007` 引导控制：后接 `0001` Ruby、`0004` 停顿、`0006` 换页、`0008` 语音、`0009` 字符串结束；`0000` 为 NUL，`000A` 可为正文换行或 Ruby 正文/读音分隔。按 UTF-16LE word 对齐解析，不在任意字节位置匹配。

Ruby 候选为 `0007 0001 + 基底 + 000A + 读音 + 0000`，语音为 `0007 0008 + 标识 + 0000`；消息可能含多个语音/分页段，不能把 NUL 一律当整条正文结束。保留顺序、嵌套及结束事件。停顿、Ruby 与物理换行默认保留；删除或合并需明确方案和运行语义证据，不因备忘录一批样本没用某控制就忽略其他输入。

研究时统计所有 code unit、代理对、私用区、C0 控制与 token 骨架，并检查 text token 中未知内容；这些分布仅帮助发现漏解析，私用区和单字节外观并非天然控制码。代码演出与文本控制分开建模，重新提取后同时核对文本、token 与 CODE/标签，不把字符串相同当演出保真。
