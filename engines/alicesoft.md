# AliceSoft：AI2 容器与 AIN 文本表

> 能力层级：`script-header-string-spans`。这是容器与文本表级参考，不是完整 AIN VM 支持承诺。

## 识别与适用范围
- `.ain` 是压缩后的字节码容器，解压体以四字节段标签串联，不是文本文件。
- 只有先通过 AI2 头校验并成功解压，才进入文本表解析。
- 本页覆盖三张带文本的段表 `MSG1`、`MSG0`、`STR0`，其余段只作为边界锚点。
- 不解释 AIN 指令与参数，不做反汇编、不重定位、不重建代码段。
- `.ex` 文件与 EX 表未实现；EXE 内嵌数据不在本页范围。

## AI2 容器
- 头部 16 字节：`AI2\0`、一个未解释的 32 位字、解压长度（偏移 8）、存储长度（偏移 12）。
- 偏移 16 起是单个 zlib 流；解压结果必须正好等于头部声明长度。
- 存储长度为 0 时只按实际剩余字节解压，非 0 时必须等于剩余长度。
- 流结束后不得有尾随字节；解压失败、超长或截断都拒绝。
- `unpack` 只读，`repack` 复用原头部并更新两个长度字，重新解压比对后才返回。
- 不做：头部两个未解释字的语义、多流拼接、`AI2` 以外的容器变体。

## AIN 段与文本表
- 解压体是若干 `标签 + int32 条数 + 内容` 段，标签为 4 字节 ASCII。
- `MSG1`：`int32` 条数、`int32` 保留字，随后每条为 `int32` 字节长度加密文字节。
- `MSG1` 的密文逐字节满足 `b = b - i - 96`（解密），加密为 `b = b + i + 96`；`i` 从 0 起按槽内偏移计算。
- `MSG0` / `STR0`：`int32` 条数，随后是 NUL 结尾的明文字符串，不解密。
- 段表必须结束在下一个已知标签或文件尾，否则不承认该处为表。
- 扫描按字节推进，遇到标签先试解析；解析失败只前进一字节，不把正文里的标签字样当成新表。
- 空串槽位（长度 0）保留但不可写，不回填成空串。
- 不做：`MSG1` 保留字段语义、其他段的布局、字符串池共享引用。

## 回写约束
- 回写是定长槽位替换：目标编码后不得长于原槽位字节数，超长直接报错，不截断。
- 短文本用 `0x20` 补齐；`MSG1` 的填充与正文一起参与同一次加密，解密后得到的是正文加空格。
- 不用 NUL 补齐：NUL 会把一个槽位读成多个空串，改变后续槽位身份。
- 结尾为空格的新文本拒绝，因为读取时会剥除尾部空格，无法原样表示。
- 空文本与含 NUL 的文本拒绝；默认 CP932 严格编码。
- 写入基于输入副本，调用方负责落盘；重新解析后逐条比对表名、槽长与文本。

## Python 接口
```python
from python.archives.ain import repack, unpack
from python.engines.alicesoft import read_ain, rewrite_ain

raw = unpack(ai2_bytes)                 # 解压 AI2
tables, texts = read_ain(raw)           # 三张表按流内顺序
patched = rewrite_ain(raw, {0: "短い"})  # 定长回写
result = repack(ai2_bytes, patched)     # 重新压缩进原头部
```

- 容器模块：[ain.py](../python/archives/ain.py)，`unpack(data) -> bytes`、`repack(original, raw) -> bytes`。
- 文本模块：[alicesoft.py](../python/engines/alicesoft.py)。
- `read_ain(raw, encoding="cp932") -> (tables, texts)`；`AinText` 给出 `table/index/offset/length/encrypted/text`。
- `rewrite_ain(raw, {index: text}, encoding="cp932") -> bytes`，索引对 `texts` 顺序。
- 函数不读写磁盘，不导入 VM 或来源库。

## 部署条件
- 回写后必须重新 `unpack` 验证压缩体，确认长度字与流一致。
- `MSG1` 槽位内的空格填充是可见文本的一部分，长度受限时优先改短而不是截断。
- 槽位增长会移动后续所有段与代码地址，本模块不提供该能力。
- 游戏字体、编码与显示效果需另行验证，编码成功不等于能显示。
