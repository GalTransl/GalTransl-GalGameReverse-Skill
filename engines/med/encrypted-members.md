# MED / 加密成员与 artemina 方言

来自[工程备忘录](../../provenance/translation-engineering-notes.json)及 GARbro `ArcFormats/DxLib/ArcMED.cs` 的 FudegakiEncryption 算法核对。只是资料；当前[MED 工作流](../med.md)仍只支持明文 MDN0 与其明确的 opcode/shape，不新增加密包提取或重封能力。

## 容器与成员分层

备忘录写 `MDE0` magic，GARbro 仅检查头前两字节 `MD`，当前 Python 严格检查 `MDN0`。这些条件不能当成可互换版本；未知 magic 应补独立 profile，不放宽现有 parser。索引头/条目宽度与 size/offset 规则可参考[归档算法](../garbro/ArcFormats/DxLib/ArcMED.md)，名称 CP932/NUL 槽中的终止后残留、保留字段及成员间隙均保持。

容器索引明文不意味着所有成员明文。脚本层候选头为 16 字节，`LE32[0]+16 == file_size` 仅说明声明长度吻合，也是加密类的条件线索；该字段没有标记密文，不能以它单独判断或验证密钥。普通媒体、其他 script encryption 与此加法方言分开。

## Fudegaki 加法与相位

该来源算法使用显式关键字的 CP932 bytes 作为非空 key。头 `0..0x0F` 保持不动；从文件绝对偏移 p=0x10 起，解密 `plain[p]=(cipher[p]+key[p%len(key)])&255`，加密为减法。key 相位以整个成员位置取模，不能把 p-0x10 当下标，不能给全归档施加该变换。

已知明文只能作为候选密钥研究：若某个结构已可靠确认有 `#RULE_VIEWER` 等固定字段，对候选周期 K，求 `key[(0x10+j)%K]=(plain[j]-cipher[0x10+j])&255`。来源文字曾反写减法方向；上式与加法解密一致。相同周期位置必须一致，候选需跨多个独立字段/成员验证全部头、帧长度、字符串池与引用。短重复前缀可能对应多个周期，不能选择第一个“像日文”的结果。文件名、注释横线及标记出现都不能替代已知明文证据，不随包内置具体密钥。

## 脚本语义兼容条件

备忘录的明文线索为：总长减16、代码长度、两个 u16 池计数、代码相对 u16 标签表、主字符串池和标签名池；帧是 `u16 source_line + u8 hint + u8 opcode + 参数`，整帧长 hint+3。末端零哨兵、参数形状及引用角色须匹配现有 profile 后才能交给 writer，hint 能划帧不代表未知 opcode 已有语义。

仅按 opcode 或日文外观导出所有池项会混入资源、规则表、导航菜单和标题。姓名是否持续、清名指令、正文显示调用与选择目标应按当前 VM 核对；备忘录的“姓名只影响下一句”“首次译名优先”不能覆盖现有 MED profile 已验证规则。共享池项可能同时是对白和资源名，应按引用隔离变化，而不是改整个原槽。

实现加密方言后，需要明文 parser/writer 往返、变长重解析、加减法及正确相位向量、密钥候选反例、恢复密文后再解包/解析和未改成员检查。索引能列出或加密变换能自反往返，都不能证明密钥及文本语义正确；无实际显示验证时仍明确未验证。
