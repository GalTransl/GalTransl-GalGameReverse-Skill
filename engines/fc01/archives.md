# F&C / FC01：MRG 与 mrg0 归档

这是归档算法资料，没有随包 parser/writer；没有执行真实解包、重封包或游戏显示验证。FC01 是来源目录标识，并不表示该目录内的 AGSI、BDT、SCXA 均为同一格式。AGSI 见 [AGSI](../agsi.md)。出处与许可见 [来源记录](../../provenance/garbro-archive-notes.json)。

整数默认为小端，算术按字段宽度溢出；文件名按 CP932 的有界 NUL 字符串处理。格式识别必须校验索引和成员范围，不只看扩展名。

## MRG：旋转/XOR 索引

| 文件偏移 | 字段 |
|---|---|
| `0x00` | `MRG\0` |
| `0x04` | `u16 key1index` |
| `0x06` | `u16 key2index`；该 reader 仅接受 0 或 1，非零时 key1index 不得为零 |
| `0x08` | `u32` 数据基址；减 `0x10` 得加密索引长度 L |
| `0x0C` | `i32` 成员数 N |
| `0x10` | 加密索引；每条步长 `0x20`，需末尾偏移哨兵 |

解密后的条目：`+0x00` 的 `0x0E` 字节名称，`+0x0E u32` 解压大小，`+0x12 u8` method，`+0x1C u32` 文件绝对偏移。当前条目的尺寸是下一条 `+0x1C` 偏移减当前偏移；最后一个终止偏移应等于文件长度。名称和未解释字段保持原样。

索引每字节解密：`plain[i] = rol8(cipher[i], 1) XOR key`，随后 `key = (key + L - i) & 255`。初始 key 不是头部两个索引值直接相加；来源的有效路径由终止偏移反推：从最后密文字节取得 `q = rol8(cipher[L-1],1) XOR (file_size >> 24)`，按逆序先递减 `2、3、4`，分别还原其余三个终止偏移字节；验证完整 u32 等于 file_size。再递减 `5..L` 得到解密首字节所用 key。未通过终止偏移校验不能采用该猜测。

| method | 成员解码顺序 |
|---|---|
| 0 | 原始跨度 |
| 1 | MRG LZSS |
| 2 | MRG range 解码后，再做 MRG LZSS |
| 3 | 仅 MRG range 解码 |

来源对 method 大于 3、部分短成员退回原始字节；独立实现应报告未知/未解码，不能宣称明文。所有压缩结果必须精确达到条目声明大小。

### MRG LZSS

初始 4096 字节全零环形窗口，写入位置 `0xFEE`。每个控制字节低位先读；1 表示一个 literal，0 表示小端 u16 token。回指起点为 `token & 0xFFF`，长度为 `(token >> 12) + 3`；逐字节从窗口读取并写入窗口，读写索引均环绕 4096，允许重叠。这里的 token 位布局不同于常见两字节 Okumura LZSS，不能直接替换。

### MRG range 解码

输入至少 `0x108` 字节：输出长度为 `u32le(0) XOR u32le(0x104)`；`0x04..0x103` 是 256 个 u8 频率，后面开始大端 u32 的初始 code。频率累计为 C[x]，总和 Q，逆查表按各频率重复符号构成；拒绝 Q=0、Q>65535、索引超出 Q 及输出预算超限。

初始 `b=0, c=0xFFFFFFFF, a=code`，`scale=floor(65536/Q)`。mask 初始 255，对 `(Q-1)>>8` 每右移一位把 mask 变成 `(mask<<1)|1`。每个符号：`c=((c>>8)*scale)>>8`；`v=(a-b)/c`，取频率逆查表符号 x；输出 x，然后 `b+=C[x]*c; c*=freq[x]`。全部加减乘按 u32 溢出。

归一化分两段：当 `((c+b) XOR b) & 0xFF000000 == 0`，a、b、c 均左移 8 位，给 a 补一个输入字节；然后当 `c<=mask`，先 `c=(~b & mask)<<8`，a、b 左移 8 位并给 a 补字节。所有除法前要求 c 非零；输入不足必须报错，不沿用来源的提前返回/零填充。普通 MRG 不设置频率表 key；别的成员格式若带 key，不可默认套用本路线。

## mrg0：顺序成员

`0x00` 为 `mrg0`，`0x04 i32` 成员数，`0x08 u32` 数据起点；索引从 `0x10` 开始，每条 `0x4C` 字节。`+0x00` 是 64 字节名称，`+0x40 u32` 是尺寸，其余 8 字节保持不透明。成员顺序紧密累加，第一条偏移为数据起点。来源没有对该格式实施索引解密或成员解压。

独立 reader 还须验证 `0x10 + N*0x4C <= data_start`、每次偏移相加不溢出、所有跨度在文件内，以及未知头字段和残留区；不能因为 reader 未解释就丢弃。

## 同签名 MRG/2 的边界

`MRG/2` 在来源中标为 Overture，头部 `+6 u16 >= 2`，不是上面的旧 MRG。索引步长 `0x57`，名称 `0x40` 字节，`+0x41 u32` 解压大小、`+0x45 u16` method、`+0x4F u32` 偏移，并使用下一条偏移哨兵。

归档名/成员名参与校验种子：初值为大写首字符；依次遍历全名（包括首字符再次参与），跳过 `.`，执行 `s = s + upper(ch) + (s<<6)`，保留 u32。空名返回 0。非 ASCII 名称要明确字符大写与编码语义，不能用不同语言的默认大小写折叠替代。

生成 256 字节 XOR 表：每轮 `n = key + rol32(checksum,16); key = checksum; checksum += n; table[i] = checksum & 255`，随后每字节 XOR `table[i&255]`。索引以归档名 checksum 和 `0x285EE76F` 为初值；method 0 成员以成员名 checksum 和归档名 checksum 为初值。

MRG/2 的 method 1 为 LZSS，method 2 为 range，method 3 为 range 后 LZSS；与旧 MRG 的 method 2/3 含义相反。选择 writer 前必须区分版本。

## 回封与文本边界

两种 F&C reader 和 MRG/2 都明确 `CanWrite=false`。上述规则足以研究读取算法，不是已验证的封包器。回封须保留索引未知字段、终止偏移、版本、原名及加密种子；压缩策略和运行时能否接受 stored 成员还需证据。解包后仍须独立识别剧情成员的编码与语义，不能把任意资源字符串导出为对白。

[工程备忘录](../../provenance/translation-engineering-notes.json)补充的 manifest 思路可用于未来 writer：保存原索引顺序、名称槽原始 bytes、头/版本、method、存储/解码长度、未知中间字段、哨兵和残留区。未改成员保留原压缩流；已改成员必须用其 method 对应的真实 encoder 重建，不能把 method1 的数据偷换为别的 LZSS 布局，或未改 method 就写 stored bytes。全 literal 只有在 token 布局、声明大小、运行时输入预算和实际加载均验证后才可用，不自动等价于合法重封。整包重建仍需经过真实 reader/writer，重新列索引、逐成员解码，核对预期译文及未改 payload；复用原压缩流不等于整包直接复制。资料未提供 range encoder 或完整 writer，不宣称此 manifest 已实现封包能力。
