# KAAS / ID 表索引 VM 与 u16 文本

来自[工程资料](../../provenance/translation-engineering-notes.json)，只提供方言研究线索；没有随包 ID parser/writer、完整 opcode/CFG 或实际回填/显示验证。归档 KAAS/PB 的 GARbro 资料不代表已解析 ID 剧本。

## 表区与数据区

来源描述前部为小端 u32 数组，首值 count，表区长度 `count*4`；须确认 count 是否含首项及入口角色，不套具体样本计数/入口。表后为偶数字节长的 u16 区，每个小端 word XOR 1 解码；变换对称，但只应用于已确认的数据区。

VM PC 使用表项索引，文本 opcode 候选为十进制 12、23、52、65，其引用指向尾部相对 u16 位置。操作数所在表/数据记录和完整指令宽度仍待核，不能凭 opcode 候选遍历。尾部增长可能无需移动表索引跳转，却需要更新文本 word 引用；引用基址、单位和合法目标须独立证明。

## CP932 字节序纠错

备忘录把数值 `0x8349` 的小端内存字节 `49 83` 解释成“オ”，该例错误。严格 CP932 解码的“オ”为 **83 49**；若按小端 u16 保存这两个字节，word 数值应为 **0x4983**。`49 83` 以未完成双字节 lead 结束，严格解码失败。

因此不能从原例推出实际文件的字符打包顺序。应对 XOR 后的数据取真实字节样例，与显示/加载器的 word 转字节逻辑交叉核对；区分小端字段读值与 CP932 字节顺序，不默认翻转所有字符。编码失败阻挡该成员，不用 replace/ignore 继续。

## 文本段、选项与控制块

记录以完整小端 u16 值 1 分隔物理文本段；正文可能把标点单独放一段，先按结构合并逻辑记录，再决定导出，不能提前丢弃单字/标点。选择列表使用相同分隔值时却应逐项导出，不按正文规则合并。控制值 2/3 与后续 word 记录分页/语音/立绘等信息，但参数数量未完整给出，必须补齐后才跨越控制块。

某些文本实际为图片姓名占位；依据引用角色和显示路径标为只读/非正文，不按字数或固定字符黑名单过滤。末端零填充须由代码覆盖及表范围确认，不把未知 word 宣布为 padding。

## 回写条件

只有完整记录及引用定义后才重铺尾部、更新已证明的文本指针。若启用按 CP932 字节折行，每段在字符边界结束，分隔写完整 `01 00`；u16 数据区需偶数跨度，但如何处理奇数字节尾部及填充值要以加载器为准，不默认全角空格能补齐奇数。选项不套正文折行，等待/资源控制块保持结构。

验证原文真实 parser/writer 往返、文字及独立标点保留、选择数量与目标、变长 word 指针、非文本表值及控制块不变、严格编码和奇数布局拒绝，再重新 XOR 并重新解析。没有完整 VM 或控制布局时仅作研究，不能交付部分字符串提取为完整支持。
