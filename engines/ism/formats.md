# ISM / ISA 与脚本重布局

来自[工程资料](../../provenance/translation-engineering-notes.json)，仅格式研究；没有随包脚本 parser/writer、实际回封或显示验证。ISA 的邻近版本见[GARbro 摘录](../garbro/ArcFormats/Ism/ArcISA.md)。资料间存在布局冲突，须先确定版本，不能拼接字段。

## ISA 归档方言冲突

候选头为 `ISM ARCHIVED` 或 GARbro 的 `ISM ENGLISH ` 分支。`+0x0C` 为计数，备忘录称 u16，GARbro 按 i16 并检查正数；`+0x0E` 为 u16 版本/flags，高位 `0x8000` 表示索引加密线索。

| 证据 | 自 `0x10` 起的索引布局 |
|---|---|
| 备忘录 | 总长 `0x30`：36 字节名称、u32 offset、u32 size、u32 reserved |
| GARbro 长名路径 | `0x30` 名称，再 `0x30` 字节后部，总长 `0x60`；offset 在条目 `+0x34`，size 在 `+0x38` |
| GARbro 短名路径 | `0x0C` 名称，再 `0x14` 字节后部，总长 `0x20`；offset 在 `+0x10`，size 在 `+0x14` |

这三种不能按相同 entry_size 读取。以完整索引、名称编码、成员跨度和加载器版本判定；不得仅因其中一种能列出可读名字就采用。保留名称原始槽、顺序、未知字段、间隙及尾部，不机械要求重包大小增量等于明文增量。

记录的索引变换：索引字节长 L，完整 dword 数 N=L//4，第 i 个小端 u32 XOR `~(L+N-i)&0xFFFFFFFF`，变换对称。范围起点、非四字节尾部和 flags 关联必须确认。GARbro 摘录虽含 DecryptIndex，但 TryOpen 未调用它；因此 flags 或 helper 存在不证明该 reader 能解加密索引。算法只能用于已确认的索引范围。

## 脚本入口与控制流

备忘录给出小端字段线索：`+0x0C` 文件大小、`+0x10` code_base，`+0x1C` 后入口记录可能为 12 字节、包含代码相对入口；另有函数表和 `FF 01` 标签表。计数来源、各记录字段及标签布局不完整，不能据此实现完整头解析。

变长内嵌文本会移动代码；须从代码指令及头部/函数/标签入口统一生成标签，再回填相对地址。`op_0F` 的 switch 引用需要区分 range 与 sparse 表；备忘录中的 sparse marker `-0x02000000` 是有符号辨识线索，不给出完整表长，不能猜成 `2+count*2` dword。合法目标必须落在已证明的代码边界。

未给完整 opcode、表达式、字符串记录和压缩/混淆算法。本页不能作为全 VM 模板；未知指令或表结构阻挡当前成员，不按字节搜索抓字符串。

## 姓名池与重编码

姓名可能先内嵌定义，后由 `op_45.strref` 引用；需解析目标字符串，而不是沿用“上一句姓名”。同一姓名池的译名必须一致，冲突时明确拒绝或按已证明规则拆分引用，不能采用首次/末次修改优先。

记录区分明文和外层编码。已修改的脚本需从新布局重新识别字符串记录，再恢复其加密/压缩；旧 codec manifest 只能核对原件，不能拿旧偏移处理新数据。算法尚缺时保持“未完成外壳”，不把明文脚本当部署文件。

实现后依次验证：原文真实反汇编/重建、变长文本与全部入口/switch、重编码解码、重包后成员回读。未改成员的解码 bytes 与身份保持，密文是否一致另按 codec 规则核对；游戏加载和跳转独立验证。
