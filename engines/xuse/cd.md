# CD / RIO 路线：签名指令与 sub_block

[工程资料](../../provenance/translation-engineering-notes.json)将此路线归为 XUSE；`.cd`、RIO 路径和 XOR53 只是结构线索，实际引擎家族仍须核对加载器，不能据此认定所有 Xuse 都使用该布局。本页没有随包 reader/writer、完整签名表、真实往返或游戏显示验证；与[GD/DLL 及周期 XOR](../xuse.md)是独立路线。

## 头、指令区与数据区

记录布局默认小端：

| 偏移 | 字段 |
|---|---|
| `0` / `0x10` | 各 16 字节 MD5 形态数据；其用途/计算输入未完整给出，原样保留 |
| `0x20` | `0x104` 字节 RIO 路径候选，逐字节 XOR `0x16`；不是可信输出路径 |
| `0x124` | u32 index_item_count |
| `0x128` | u32 data_size，指令区长度 |
| `0x12C` | u32 config_flags |
| `0x130` | count 个 12 字节索引项，第三个 u32 为指令区内偏移线索 |
| `0x130+12*count` | data_size 字节指令流 |
| 指令流后 | sub_block 数据区，直到文件末 16 字节 |
| 文件末 16 字节 | MD5，备忘录描述覆盖此前全部 bytes |

先限制计数/大小，验证各跨度、索引目标及尾校验。头部两个 hash 不等同末尾完整性校验，不能随内容更新成同一个 MD5。

## 签名匹配与块引用

指令签名可能长 2/4/8 字节；其中固定 FF 是实际字节，不是通配符。存在前缀重叠时最长匹配优先，并按对应 u16/u32 参数 schema 取数。资料只列少量签名，不能拿短表遍历整文件；未知签名阻挡成员。

仅部分操作数指向 sub_block，其他数值可能为标签或跳转。完整定义引用类别后，按有效块起点建立跨度；不假设代码中出现顺序就是物理偏移排序，需核对重复/共享引用、终点和未引用范围。来源所述相邻偏移切块法只能用于已证明单调、完整覆盖的布局。

## XOR53 文本与逻辑记录

字符串候选是 `u32 byte_length + XOR 0x53 的 CP932 bytes`。对话块候选结构：u32 opaque_id、u32 text_content_length，内容为 u32 opaque_parameter、u32 segment_count，随后逐段长度+加密文字；之后 u32 other_content_length 与不透明附加数据。各内外长度必须精确匹配，附加数据保留，不按可读文本扫描修改。

count1/2/3 可对应旁白、姓名+正文、姓名+多段正文，但这是方言语义候选；不能据槽数确定所有块角色。记录签名 `40 00/41 00` 为对话候选、`6A 00/68 00` 为选择候选；前者选择形状可能带三个 u32 参数，后者连续长度字符串，其终点仍依已确认块边界。

允许合并显示段时须确认自动折行与事件边界，保存原组成槽和控制关系；选项逐项保留。XOR 对称和可读日文不是完整语义提取证据。

## 变长重建

按原物理布局及共享关系重建已解释块，建立旧/新块起点映射，只更新 schema 声明的引用操作数；保留全部其他指令参数和未知区域。若代码长度变化，同步修复索引、跳转和 data_size；仅改 sub_block 时不能误把新块大小写成代码大小。重新组装后更新已证明的长度及尾 MD5，再解析、校验全部目标及非文本结构。缺完整签名/引用表时不回写。
