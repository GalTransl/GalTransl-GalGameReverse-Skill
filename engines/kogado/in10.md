# Kogado / IN10、KGO 栈式 VM

本页为[工程资料](../../provenance/translation-engineering-notes.json)中的方言线索，没有随包 KGO reader/writer、完整 opcode 表或真实回写/显示验证。IN10 同时可见于场景表与脚本，不能只凭 magic 选择 parser；不同于 GARbro 的 Kogado 归档及 Cocotte 压缩算法。

## 场景表与三段脚本

场景表候选头：`IN10`、`+4` 记录区长度、`+8` 记录数，`+0x0C` 开始以 u16 总长度串联记录；名称线索在记录 `+0x16`，`+0x0A` 为主段相对入口信息。脚本 ID 与脚本成员关联，但 ID 字段宽度/位置、名称终止方式及入口基址未完整给出。场景导航显示文字不自动归为剧情选择。

KGO 记录为 64 字节头与三个主要段，小端：

| 头字段 | 线索 |
|---|---|
| `+4` | 文件总长 |
| `+0x1C/+0x20/+0x24` | 主段偏移、大小、记录数 |
| `+0x28/+0x2C/+0x30` | 调用/回调段偏移、大小、计数 |
| `+0x34/+0x38/+0x3C` | 文本段偏移、大小、记录数 |

主段含函数记录和 VM，第二段含调用记录，第三段为文本槽。记录长度、文本编码长度/终止和其他头字段未完整定义；不得把三段原样保留就当完成解析。特别是 aux_hint 未被证明为代码末尾时，不以它截断函数，需结合记录界限、入口和终止指令核对。

## 栈引用与显示指令

记录 VM 为 32 位整数栈，opcode 为小端 u16；`0x01/0x03/0x04/0x05` 记录为 6 字节，后三者带相对指令起始 PC 的有符号 i32 跳转。其他有效指令的长度不能一律猜成 2，需完整派发表/变体证据。指令不强制四字节对齐。

| opcode 线索 | 角色 |
|---|---|
| `0x40 Text` | 消费栈中文字引用并写入显示缓冲 |
| `0x41 NewLine` | 推进物理显示行 |
| `0x42 NewPage` | 请求新页 |
| `0x48 Ruby` | 关联正文与读音引用 |
| `0x4D KeyWait` / `0x4E PageWait` | 两种等待，不是普通换行 |
| `0x51 Select` | 消费四个栈参数；参数的文字/目标角色须核对 |

文本引用在记录方言中为 1-based，metadata 可用 0-based，但必须显式转换。`PUSH + Text` 与直接给 Select 的 TextRef 不同；给 TextRef 凭空增加 Text 会改变 VM 行为。提取前确认栈来源，不仅看紧邻指令的数值。

## 逻辑消息、槽与等待

分别保存文本槽身份、引用指令、物理行分组、等待和分页事件。一条消息可能覆盖多个槽，空槽也可能属于显示结构；不能按空串、引号或等待单独判句尾。排版所需行宽是 profile 参数，不内置备忘录某个样本的 44 字节。

增加行须同时重建文本记录、显示引用及 NewLine 等指令，并更新函数记录长度、后续记录位置、入口/跳转和头部段字段。仅追加文本槽而没有引用不会显示；仅插指令而未更新函数边界会破坏 VM。

KeyWait 与 PageWait 默认保留。将句内等待改成换行、删除 Ruby/读音槽等是改变显示行为的可选方案，只有已确认语义和明确需求时采用；不能以“译文较长”自动触发。Ruby 正文可能被普通 Text 共享，删除读音后若重新编号，需修复全部 Text/Select/Ruby 引用，不能丢弃仍在使用的正文。

有界实现完成后验证原文重建、变长及增槽、TextRef 不增显示指令、共享 Ruby、等待位置、入口/跳转合法性与非文本结构；游戏显示与点击选择的实际去向另行验证。
