### GXP v100：头部检查与原始区域读取

[gxp.py](../python/archives/gxp.py) 仅检查版本 `100`、标记 `0x10203040` 的固定头及数据范围。它接受 `bytes` 或可 seek 的二进制流；使用流时头部检查只读取 48 字节并恢复流位置，不载入整个媒体包。

| 偏移 | 类型 | 字段 |
|---|---|---|
| `0x00` | 4 bytes | `GXP\0` |
| `0x04` / `0x08` | u32 LE | 版本 / 标记；其他值拒绝 |
| `0x0C` / `0x10` / `0x14` | u32 LE | 原始标志，暂不解释加密语义 |
| `0x18` / `0x1C` | u32 LE | 声明成员数 / 声明索引大小 |
| `0x20` / `0x28` | u64 LE | 数据区大小 / 数据区绝对偏移 |

数据区不得覆盖固定头或越界，且 `data_offset + data_size` 必须等于文件大小。`index_bytes()` 返回 `[0x30, data_offset)` 的完整不透明区域；**不假定其中有固定长度前置块**，也不根据 `0x1C` 与实际区间的差值跳过字节。声明索引大小与记录边界的关系仍需索引解码器核实。

`read_member()` 只读取数据区内的**原始字节跨度**。调用方必须已有独立验证的索引项，才能提供相对数据区的 `offset/size`；范围合法不证明其确实是一个成员。返回值可能仍被加密或封装，不能标为已解包明文。传入的缓存头也会与当前输入重新核对，防止错用其他文件的头部。

索引区域默认预算 16 MiB，单次数据读取默认 64 MiB；可通过 `max_size` 显式调整，读取前检查。批量调用还须由上层限制成员数和累计输出。

```python
from python.archives.gxp import read_header, index_bytes, read_member
with open("/path/to/archive.gxp", "rb") as stream:
    hdr = read_header(stream)
    raw_index = index_bytes(stream, hdr)
    # offset/size 必须来自另行确认的索引项；这里没有索引解码器。
    raw_member = read_member(stream, offset, size, hdr)
```

此模块没有文件名解析、成员解密、解压或 writer，不能用于宣称 GXP 解包/重封包已支持。

## MWB 包装
- [unpack_mwb](../python/engines/gxengine.py#L20) 返回完整解压 payload。
- `LE32[0x14]` 是未压缩大小，`LE32[0x18]` 是存储大小。
- 实际正文从 `0x1C` 开始。
- 两大小不同则执行 zlib 解压；相等时按原始未压缩正文处理。
- 存储大小必须精确等于文件尾正文长度。
- 默认最大输出 64 MiB，可由调用方显式降低或提高预算。
- 解压必须达到 EOF、没有额外尾流、没有超量输出，并精确匹配声明长度。
- 任何不满足的文件直接报错，不沿用源“提示后继续”的宽松行为。

## 混合端序文本记录
- [scan_fields](../python/engines/gxengine.py#L37) 扫描已知六字节标记。
- 预设 pattern 为 `[08/05] 1A 00 00 [00..02] xx`。
- 末四字节其实是**大端**文本 byte_length。
- 因而该 pattern 限制已核实字段长度为 `0..0x2FF`。
- 标记 `08` 与 `05` 不应简单归并成同一语义。
- 源预设提醒 `05` 是控制字符串，可与 `08` 分开提取以免误译。
- Field.kind 保存首字节，让调用方在翻译前显式分类。
- Field.length_offset 指大端长度位置，start/end 指原始正文跨度。
- 扫描完成后所有未命中前缀、间隙和结尾仍留在 payload 中。
- 匹配标记但长度越界时拒绝，而不是把它解释为“没有台词”。
- 编码默认 UTF-8，与源初始化一致；也允许显式指定经过验证的编码。
- 无法解码的候选会报错，不像上游继续跳过造成静默漏提。

### 分区与符号引用的识别

MWB 的字符串候选可能来自符号表、指令名表或代码区。提取前先确认各区的边界与引用关系，再选择可翻译字段；含假名、汉字或 `.txt` 后缀都不足以判定剧情语义。

若观察到“名称、所属文件”交替排列，可将其作为符号表候选，通过数量字段、记录边界及代码引用交叉核对。未确认布局时不按固定数量切区，也不把剩余全部记录直接认作代码。已经确认的变量名、脚本名和跳转目标必须保留，即使它们与显示文字相同。

当前 `scan_fields()` 只扫描局部字符串标记，没有实现上述分区或完整指令集。指令名表中的 `text`、`endtext` 等字面字符串不能当作消息开始/结束指令；必须先解析所属区与引用语义，不能靠全文件字符串配对修补误分类。

## name/message 与控制保护
- 源预设 `名字「正文` 的 name 长度限制为 1 至 10 个字符。
- ASCII-only 字段、开头大写命令或 `@`、包含下划线的字符串可能被跳过。
- 这些是特定提取规则，不意味着所有非 ASCII 字段都适合翻译。
- 本 leaf 返回完整字段，不用猜名结果覆盖结构内变量。
- 建议先按 kind 筛选，再将已确认文本交给 name/message 规则。
- UTF-8 字符数和字节数必须区分，长度字段永远写字节数。
- 控制标签、换行和资源标识的完整性由上层语义策略保护。

### 消息边界与姓名证据

只有确认指令语义和操作数布局后，才能把局部字段组合为 name/message。若方言使用 `text` / `endtext`，须证明这些记录是代码中的消息指令，并验证配对、嵌套和异常边界；不能仅取相邻同名字符串。

- 姓名应来自明确的姓名操作数、角色定义表或已证实的显示上下文。短串、引号、立绘名或语音前缀仅作核对线索，不作为猜名兜底。
- 语音 ID、资源名只在已确认的结构槽中排除，不按字符串外形无条件删除；类似 `abc0001` 的正文也可能是合法显示内容。
- 保存消息字段与原记录位置的对应关系，核对正文、姓名、选项、重复项及顺序。物理文本行的展开比对可帮助查漏，但不能替代控制码、字段身份和非文本结构校验。

这些是扩展语义层时需要证明的条件，当前局部 reader/writer 没有完整实现。

## 本地回填
- [replace_fields](../python/engines/gxengine.py#L57) 接受字段序号到 str 的映射。
- 它从原文件重新解包和解析，避免对已移位 offset 二次使用。
- 从后往前替换文本与其四字节大端长度，保留所有其他 bytes。
- 译文编码后超过 `0x2FF` 时拒绝，不生成本 reader 无法再读的标记。
- 重组 payload 后重算 MWB 的两个小端大小。
- 默认用 zlib 压缩，也可明确选择不压缩。
- 若压缩后恰好与原始 payload 同长，使用原始 payload 避免大小判定歧义。
- 这里重建的是源代码覆盖的本地字符串布局，不是整个 GxEngine 指令集。
- 若目标版本另有全局跳转/索引，须先补充验证，不能套此 writer。
- 外层容器索引和文件部署由公共层/专用工具另做。

### 回填验证

内联长度字符串的存在不能证明没有全局指针。批量回填前须确认目标方言的地址、索引和校验关系，再验证：

1. 全部原文真实经过 parser/writer。确定性未压缩格式要求字节一致；重新压缩产生合法差异时比较解压内容与非文本结构并说明原因。
2. 变短、变长中文写入后重新解析，核对文本、长度、引用目标及未修改字段。抽出非文本字节相同只证明内容保留，**不证明它们的绝对位置未变或指针仍正确**。
3. 将译文换回原文后再次比较结构与内容；可逆性仍不能代替运行时加载验证。

统计扫描命中率既不能证明存在指针表，也不能排除指针。地址语义未知时继续研究，不能以往返自洽为由发布整文件回填成功。

## 调用示意
```python
from python.engines import gxengine
payload = gxengine.unpack_mwb(member_bytes)
fields = gxengine.scan_fields(payload)
# 先确认 fields[0].kind 属于需要翻译的文本类型。
result_bytes = gxengine.replace_fields(member_bytes, {0: "译文"})
```
- source member 必须处于原包装状态，不能把 payload 直接当 member_bytes。
- 不依赖 `ExVar`、PyQt5、原 tools 或相对工作目录。

- 合成测试验证大端字段长度与小端包装长度的组合。

- 测试覆盖越界标记和超出解压预算的拒绝。
- GXP 固定头、原始区域边界、流式读取预算和坏输入拒绝见 `tests/test_gxp.py`（合成样例）。

- 未实现 GXP 索引项解码与封包、V2 剧本转换、字库扩展和完整控制字段识别。
- 文本解析成功不能替代 UI、分支、存档等部署回归。
