# TUITUI / SPT60、SBY 与 FF DAT 字库

来自[工程资料](../../provenance/translation-engineering-notes.json)的研究线索，没有随包 SBY/FF DAT reader/writer、完整 VM/表达式定义或真实回写及显示验证。下列数字是格式候选，需匹配目标头、加载器和边界；图像高度、字号、标点偏移不作为引擎固定值。

## SPT60 入口与指令

SBY 候选头为六字节 `53 50 54 36 30 1A`（`SPT60` 加 `1A`）；`+6 u16` 的版本/常规入口计数角色尚需区分，`+8/+0x0C` 给特殊入口表数量与地址的线索。普通入口记录、计数宽度及保留字段未完整定义，不能直接把 `0x10` 后全部当代码。

记录方言的入口表保存绝对 u16 文件指针，`FFFF` 为无入口；`0x57 TEXT` 含 CP932/NUL 字符串，表达式 `0x03 STRING` 也含同类字符串。`0x55/0x58/0x59` 记录为相对指令末尾的 u16 位移；符号/环绕及具体操作数位置仍需核对。代码和表达式指令集分别覆盖，原文解析成功不能替代完整表。

变长 writer 需重新布局代码、更新入口及跳转，并验证 u16 容量；不按二进制正则抓 TEXT，表达式里的资源字符串也不能一律导出对白。

## 文本与图片姓名

`$N/#E/#C`、`$L/$1/$8`、`#C;` 为控制候选，含义与组合必须按方言解析。首尾 token 可保存在 metadata，句内 token 保存精确的段/槽关系；不能按译文字符比例“近似恢复”。来源记录以圈号等字符指代图片姓名，只有显示链确认后才标为只读姓名，不把所有同字符当人名，也不虚构对应译名。

已确认自动折行时，可将纯排版 `$N` 的物理行合并；等待、定位、分页及图片姓名控制仍保留。默认不删除全部 `$`/`#`，普通正文可包含这些字符。回填从可靠原件重新解析并核对源哈希、TEXT 身份与 token，已提供空/缺失 message 不静默回退。

## FF DAT 位图页

字库候选为 RLE 包装的 4bpp 灰度 plane；来源未给 RLE token 算法，不能仅凭图像尺寸实现 DAT 重封。每存储字节含两个像素，需先确认高/低 nibble 的左右顺序。记录显示 plane 上下翻转：解 RLE、展开 nibble、翻到显示方向、处理字形，再逆向翻回、量化、RLE 回封。宽高与 stride 均从结构取得。

记录方言字槽为 32x32，plane 宽 512，即 16 列；以下定位仅用于头与加载器已匹配的方言：

| 页 | 双字节 lead 范围 | 页内行/列 |
|---|---|---|
| FF_00 | `81..8F` | 行=`12*(lead-0x81)+max((trail>>4)-4,0)`，列=`trail&15` |
| FF_01 | `90..9F` | 行=`12*(lead-0x90)+max((trail>>4)-4,0)`，列同上 |
| FF_02 | `E0..EF` | 行=`12*(lead-0xE0)+max((trail>>4)-4,0)`，列同上 |

先筛选合法 CP932 lead/trail、严格解码及别名，再检查槽是否落在当前 plane。未给出的单字节、其他页与渲染路径不猜。采用共同 JIS 映射时需要确认代理码实际可寻址，不只检查 Python 能编码。

FF_00 可能混入图片姓名/装饰区域。备忘录方言指出显示方向的槽行 72..77，保护范围覆盖整行；该坐标只能作为目标 profile 的核查候选，不能对所有字库强制套用。通过像素内容和渲染引用确认保护区，重绘后逐像素核对未变，不能只比较 DAT 大小。字体文件、字号、灰度、标点 dy 与保护 mask 都需显式参数和视觉检查，不随包带入原字体或位图。

字库与脚本应使用同批映射。验证重新解码后的尺寸、像素方向、合法槽定位、保护 mask 不变、未解决字符清单及脚本 u16 引用；显示检查包含图片姓名、标点、原日文和中文，不把普通 TTF 替换当已覆盖位图路线。
