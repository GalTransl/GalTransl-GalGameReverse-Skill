# 编码、控制码与二进制重定位

正文确定为 CP932 时，中文回注优先考虑 [JIS 替换公共接口](jis-substitution.md)：保留真实中文 JSON，输出匹配的 UIF 配置与映射，并在交付中说明 hook 或专用替换字体的部署方法。适用性取决于正文编码和实际显示链，不由引擎名或包内文件名编码推断。

## 四种不同的编码

分别记录：原剧本编码、资源包文件名编码、翻译 JSON 编码、回填字节编码。JSON 的 UTF-8 不意味着原游戏支持 UTF-8。

- Python `cp932` 不等同严格 `shift_jis`；不要混换。
- 编码枚举或变量名可能与实际 codec 不一致；沿调用路径核对实现，不按名称猜字符范围。
- UTF-16 字节数、UTF-16 code unit 数、Unicode code point 数和 UTF-8 字节数不同。Python `len(text)` 不能替代 C# 的 `string.Length` 或原格式长度字段。
- UTF-16 零终止符必须按 2 字节边界查找，不能任意 `find(b"\0\0")`。
- 解码时先确定 BOM/引擎规则，保留原始字节。默认严格失败，禁止 `errors="ignore"`、`errors="replace"` 或猜出一个看起来像日文的编码就继续。
- 名称、正文、资源名和不同字符串池可能使用不同编码，必须逐字段处理。

## 长度与显示是两件事

先严格编码成 bytes，再验证容量：单字节长度上限、含不含 NUL、是否为16/32位、有无4字节对齐。长度字段和地址字段可能使用不同单位；具体宽度、终止符规则与换算公式写在相应引擎页。

定长槽超限默认拒绝。自动截断即使不拆坏多字节字符也会丢译文，不能当正常成功。任何显式截断/简写策略都应由用户决定并单独报告。

存在绝对地址不等于只能定长替换：引用已完整识别且 writer 能重定位时仍可变长。没有绝对地址也不代表可任意增长，仍须核对索引宽度、计数、对齐、校验和加载器读取预算。不要用“变长后崩溃就改截断”代替格式研究。

### 分行策略与字节预算

逻辑消息、物理显示行、等待和分页分别建模。连续文本可按已确认的消息边界合并，保留组成槽/引用及控制事件；不能仅按引号、标点或等待判断所有格式的句界。选择项默认逐项保留，不套正文折行规则。

| 策略 | 必须确认的条件 |
|---|---|
| 保留原分行 | 引擎控制、槽数或演出依赖原分段；记录实际分隔而非猜成 LF |
| 依赖自动换行 | 实际显示链具备折行，移除的仅为排版换行，不是等待/分页/定位指令 |
| 按编码字节折行 | 已核实每行容量、分隔写法、续行缩进及槽/指令增长规则 |

来源中的 A/B/B3.1/B3.2 只是方案代号，应在引擎 profile 写出实际行为，不据代号选择 writer。按字节折行先逐字符严格编码，再选择完整字符边界；CP932 的 ASCII/半角字符也可能只有 1 字节，不能统一按 2 字节计数。仅在格式要求字对齐时限制偶数字节宽度，不能给所有引擎强加偶数条件。

禁则集合与续行缩进为明确的排版参数。先调整断点，使禁行首/行尾字符随邻接文本移动，再添加格式允许的填充；缩进、填充和控制参数分别计入其实际预算。单字符超限、无法满足禁则、奇数剩余空间无法合法填充或最大行数不足时明确拒绝，不死循环、不丢字、不把余文塞进超长末行。标点组合需验证，不能用插空格代替调整断点。换行字节是否计入容量依格式定义；末行不为了凑宽擅自补齐，定长槽或 u16 数据区的填充另行处理。

已有未修改记录保留原分段与 payload，仍由真实 writer 重建结构验证。缺少译文文件按主流程保留原件；已提供记录缺 `message` 或意外为空时依契约报错，不静默回退掩盖翻译失败。

能成功编码为 CP932 或 GBK 不意味着游戏能显示中文。SJIS tunneling、字符替换、UIF 和字体/运行时补丁属于单独的能力：需要匹配的映射方向、容量、渲染支持与实际加载验证。

不能照搬某些上游“未覆盖字符替成问号/全角空格”的宽松行为。缺字、冲突、代理字符和映射耗尽必须可见。

## 控制码处理

没有一套通用“删除标签”规则。先按已确认的语法分类，再制定可逆的导出与还原规则：

| 结构类别 | 必须核对的约束 |
|---|---|
| 换行、分页、等待 | 物理换行与字面控制串分开；位置、数量和还原方式明确 |
| 样式、字体、注音 | 起止关系、嵌套和属性有序保留；可翻译字段由 parser 明确标记 |
| 变量、占位符 | 保留标识与参数，不把运行时取值猜成固定正文 |
| 命令、宏、脚本区 | 区分可翻译参数与可执行内容，不把译文变成新命令 |
| 选择与跳转 | 显示文字与目标身份分离，保留分支顺序与引用 |
| 字段分隔和转义 | 按语法还原，防止译文增加字段、提前闭合或改变 token 边界 |

各引擎的具体标记、命令和方言例外放在 `engines/<id>.md`。

建议解析出不可翻译 token 并在 metadata 保存，在正文中保留明确字面量；回填检查数量、顺序/嵌套、转义和允许出现的位置。`contract.py` 只检查已列字面量的数量，不替代引擎语法校验。

不要全局替换同样文本：资源文件名、变量、分支标签、脚本命令字符串可能恰好与对白相同。

## 位置映射不是只加一个 delta

变长替换影响两类位置：**地址字段自身的位置**，以及它指向的目标位置。还可能需要文件基址、代码基址、字符串池基址、相对跳转起点、字节/字单位转换。

[common/binary.py](../python/common/binary.py) 提供受限参考：

- `apply_edits(data, edits)`：已知非重叠非空范围替换，返回中间 bytes 与 `OffsetMap`。
- `OffsetMap.map(old_offset)`：旧边界/未改字节映射；落入被替换区间内部的未知地址拒绝。
- `relocate_u32()`：只适用于调用者完整枚举的无符号32位引用，单一基址与单位。不是通用 VM relocator。

```python
import struct
from python.common.binary import Edit, apply_edits, relocate_u32

# 仅为人工二进制样例，不是某游戏格式。
original = struct.pack("<I", 7) + b"abc" + b"END"
modified, offsets = apply_edits(original, [Edit(4, 7, b"longer")])
rebuilt = relocate_u32(original, modified, offsets, fields=[0])
assert struct.unpack_from("<I", rebuilt)[0] == 10
```

每个真实格式还必须回答：
1. 是否完整解析全部 opcode，未知 opcode 的长度能否确认？
2. 哪些字段是指针，哪些只是整数或常量索引？
3. 分支表、函数入口、代码大小、异常表、线程入口是否一并更新？
4. 文本池是否共享引用，同一字符串被不同位置翻译成不同内容如何处理？
5. 长度改变后是原位重组、追加新池还是重建指令？是否需要升级长度字段？
6. 重新压缩/加密、目录哈希和校验和是否覆盖了变化后的数据？

如果没有答案，模块只能作为局部参考，不能发布整文件回填成功结论。
