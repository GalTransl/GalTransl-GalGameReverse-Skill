# 增补未知引擎或游戏变体

本 Skill 的引擎页与 catalog 保留格式线索，但没有宣称每个格式都已有 Python 全链路实现。**停止不安全写入，不等于停止只读研究或补齐算法。** 不要把最近似的 writer 直接套上去，也不要仅因旧接口拒绝就结束调查。

## 先确定缺的是哪一层

| 缺口 | 应报告的事实与下一步 |
|---|---|
| 缺格式证据 | 尚无足够布局依据；比较游戏样本、随包格式说明与人工样例，不猜长度 |
| 有格式依据但尚未实现 | 标明随包资料和样本中的字段依据；补齐独立 Python 实现 |
| 局部实现 | 标明已覆盖版本/opcode/阶段；扩展规则及正负例，不能把部分结果包装成整文件成功 |
| 缺 writer | 可继续索引、解码、只读提取；补齐指针、长度、校验和外壳后再允许回填 |
| 许可待核 | 指出真正未知的文件授权或版本兼容条件；不是看到 GPL 就停止 |
| 缺运行验证 | 交付已验证阶段和待验证条件，未经授权不部署/启动游戏 |

阶段也需拆开：容器索引 → 选中成员解码 → 字节码解析 → 姓名/正文/选项语义 → 脚本回填 → 外壳/归档 → 游戏加载。能导出字符串不代表有消息语义；能写出脚本不代表游戏能加载。

`source-registries.json` 中的 `source_only` 是**上游注册证据的状态**，不是本包 Python 的能力状态。上游注册、当前实现、测试等级分别记录，不用“支持/不支持”一个词掩盖差异。

## 查随包资料 → 样本分析与实现 → 合成验证 → 重试

1. 从 [格式目录](../catalog/formats.json)、[源注册清单](../catalog/source-registries.json) 和 [来源锁定](../provenance/sources.json) 找候选。
2. 核对随包 parser、writer、辅助算法、测试和已记录的格式约束，列出与目标样本的差异。修改已有实现时核对随包文件头与许可记录。本包已有 GPL 许可基础，**允许 GPL 移植**，保留 MIT/GPL 原声明、修改说明及相应源码义务。已明确的 GPLv2/BSD 声明需核对兼容条件，不归类成未知授权；详见 [NOTICE](../provenance/NOTICE.md)。
3. 假设无法访问上游代码。catalog 中的源文件名和符号仅作出处线索，不能当作已读过的实现证据；根据随包资料和游戏样本建立、验证格式假设。完成后算法及必要数据随 Skill 携带，不引入外部仓库或运行时依赖。
4. 写下布局：字节序、字段宽度、表项数、基址、偏移单位、压缩层、文件名编码、校验范围。区分游戏参数与自描述字段；缺密钥/表时拒绝相关变体，不默认套其他游戏配置。
5. 实现二进制算法时明确固定宽度溢出、符号位、移位/旋转、UTF-16 长度、流位置和 LZ 重叠回溯语义；不照搬宽松异常回退或缺省空 opcode 模板。
6. 移除 GUI、全局配置、动态 `eval`、相对 cwd、import 时执行和吞错；显式声明输入/输出预算与返回值。容器先提供无 payload 索引和有界小头探测，再读取选中成员，不能让大视频妨碍只读目录研究。
7. 使用人工正负例验证边界、拒绝、原文及变长往返。在新的输出目录重试目标副本，记录已通过阶段和仍被阻挡的成员；不能把未测推断升级成成功。

## 对话定位的证据

优先使用消息 opcode、字符串引用类型、文本节点或事件 code。正则只用于已确定的文本方言，必须识别注释、转义、命令区和结束标记。

保存真实定位关系，不按原文搜索替换。同一字符串池项的不同译文：创建新池项并只修复已证明的引用，或明确拒绝冲突，不能默认最后一个覆盖前一个。

姓名可能是可写字段、只读上下文、运行时变量或独立表；选择支显示文本与跳转目标必须分开。动态变量不能猜成固定姓名。未知 opcode 不能用猜测长度或空模板跳过；解码错误不能吞掉并回退原 bytes 后标为成功。遇到显式布局未覆盖的指令须阻挡整个成员，不能把失败前的记录保留为成功导出。

## 文档与实现放在哪里

- `guides/` 只保留跨引擎适用的流程、数据契约、编码原则、验证规范和实现要求。
- 魔数、文件布局、opcode、引擎控制码、参数/API 示例、具体版本限制与通用适配方法直接写入 `engines/<id>.md`。不要在通用指南目录增设某个引擎的专用文档，也不向主 `SKILL.md` 堆放这些细节。
- 多个方言先在该引擎页说明入口和分歧；已有独立方言页时用相对链接衔接。按需读取页面即可取得该格式的完整条件。
- 算法放在对应的 `python/engines/` 或 `python/archives/` 模块；人工 fixtures 放 `tests/`；文件级出处和许可放 `provenance/`；本次运行报告放在游戏结果目录的 `reports/`，不收入仓库。引擎页链接这些依据，不把源码注册数量当能力证明。
- 新增页面才按维护流程更新引擎索引；改目录或迁移段落时，同时更新正文链接、源码文档字符串和已有校验中的路径。

## 格式证据不足时的二进制研究

涉及字节码 reader/writer 时，按[VM 分析与语义重建](vm-analysis.md)记录指令边界、引用、栈语义和变长布局；已有研究线索见[脚本与字库资料](../catalog/format-research.md)。资料只给分析入口，实际能力仍以实现和验证为准。

如果随包资料和样本差分仍不能解释布局，可通过目标程序的静态反汇编、反编译或二进制差分补充证据。例如定位资源读取、密钥派生、解压、字符串解码或 VM 指令分派，再追踪与失败字段有关的路径。优先研究阻塞当前阶段的最小范围，不必先完成整个程序的逆向。

### 进入前保留已有证据

1. 固定失败层，保存源哈希、成员、版本、字段位置及可复现诊断。
2. 核对随包实现、`catalog/` 与 `provenance/`，区分“格式已知但缺实现”和“缺少格式证据”。前者直接补实现；后者明确还需要证明哪一个字段或关系。
3. 记录工具、预算或权限的实际限制，避免把环境限制误写成格式结论。

专用反汇编/反编译工具可帮助研究，但不是本包的运行依赖，也不能代替可复现的格式解析。研究所得的必要算法、数据和说明仍应随包提供，使用者无需访问外部仓库。

### 操作与验证边界

- 沿用主 Skill 的只读和输出约定：不执行未知 EXE/DLL、不使用不受限反序列化，产物写入新目录。启动游戏、安装组件或修改目标程序前核对已有授权是否覆盖该操作；不因进入逆向研究而扩大授权范围。
- 从程序行为提出布局假设，再用独立样例确认端序、长度、边界与引用关系。未知 opcode 或密钥仍需补齐证据，不猜长度、不以空模板继续。
- 已确认的容器算法放 `python/archives/`，剧情语义放 `python/engines/`；保留参考代码的出处与许可。补有界 parser/writer、合成正反例、原文往返、变长中文回写及非文本结构验证，不能只凭反汇编结论宣称支持。
- 仅发布完整通过当前阶段的成员，保留失败成员诊断；批次未完成标为 `partial`。已经验证的阶段可正常交付，不因继续研究而扣住可用成果，也不把局部成功升级为全链路支持。

最终仍缺证据时，明确报告失败层、未确认字段和下一步需要的材料。真实样本与运行记录放结果目录；可复用的识别条件、格式规则和兼容边界归入对应引擎页。游戏显示仍须单独验证。

## 最小验收清单

- [ ] 魔数与结构证据可复现，未知版本/布局拒绝；有界只读索引不依赖全部 payload。
- [ ] 至少一个实际算法，不是 `NotImplementedError` 模板或原 exe 包装。
- [ ] 原文 JSON 与定位映射可逆，不丢重复项/空项/姓名槽，不按部分解析发布成功结果。
- [ ] 真实 writer 原文往返通过；只具局部参考时明确无此保证。
- [ ] 变短/变长/多字节/共享引用/边界溢出与坏输入测试通过，预算在分配前检查。
- [ ] 对长度、地址、校验、内部数据保留及未实现外壳有解释。
- [ ] import 无用户文件 IO/进程副作用；随包运行不需要原仓库、GalTransl 或 GUI。
- [ ] 出处、修改说明、文件级许可与验证等级完整。
- [ ] 页面、API、链接与实际实现相符；新增引擎页时才按维护流程更新索引，不把标题当能力证据。

只分析随包实现但没有实际测试时，记录“随包源码分析，未执行验证”。具体游戏的只读验收与运行验证只记录在本次结果目录，不写入 Skill 文档或 `provenance/`。
