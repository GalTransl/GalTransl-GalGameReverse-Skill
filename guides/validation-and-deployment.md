# 验证、失败处理与部署

游戏无法启动时先参考[启动与区域排查](startup-and-locale.md)，区分运行环境问题与补丁引入的问题；离线提取和游戏显示分别报告验证状态。

## 能力与证据分开记录

能力分别看：识别、容器解包、脚本导出、脚本回填、重封包、游戏加载。证据分别看：

运行报告只保存在游戏结果目录的 `reports/`；Skill 文档和 `provenance/` 不积累测试执行记录或真实游戏验收案例。

1. **随包源码核对**：记录本包文件、符号和版本或哈希，不代表代码已执行；历史来源核对记录也不能充当本次执行证据。
2. **语法/静态通过**：代码可解析、依赖/路径合规，不代表算法正确。
3. **合成样例通过**：人工最小结构、正负例与往返通过，仅覆盖测试子集。
4. **真实样本往返**：记录合法样本哈希、游戏/格式版本、命令和差异。
5. **游戏运行验证**：在用户授权的副本上确认实际读取、显示和流程。

上游 README 声称的测试只能写作“上游该版本文档声明，当前未复验”。不能把局部函数的单测升级为整个引擎已通过真实游戏验证。

## 原文回填是翻译前的门槛

1. 保存原文件哈希、关键结构和原文导出。
2. 用原文 JSON 走真实 parser + writer 流程。
3. 确定性格式应字节一致；不能用“没有改译文就直接复制原文件”的快速路径代替 writer 测试。
4. 压缩、XML/JSON格式化等发生合法规范化时，说明具体差异并比较解压内容、字段、引用和非文本区。
5. 再次提取文本相同只是必要条件；指针、跳转、辅助表、校验、文件长度同样要检查。

## 变长与拒绝样例

至少测试更短、同长、更长、多字节、空文本和字段上限；对重复文本、共享引用、空表项、非连续索引做专门案例。

坏输入测试应包含：截断、数量/长度溢出、偏移越界、非法编码、未知版本/opcode、控制码丢失、名称路径穿越、规范化重名、缺少辅助文件、解压超限。

测试 fixtures 应人工构造并保留独立预期 bytes/offset，避免 reader 与 writer 共享错误后互相印证。不要提交商业游戏剧本、私有密钥或未经许可的样本。

## 按阶段与成员验收

分别记录索引、探测、解码、解析、导出、回填、外壳恢复和游戏加载的覆盖范围。索引条数不等于剧本数；解码成功不等于内层格式成立；自动重解析也不等于运行验证。

未知指令、歧义边界、非法目标或解码错误必须阻挡整个成员。只发布完整通过当前阶段的成员，失败前的部分行仅作诊断。`empty`、`blocked`、`skipped`、`non_target` 与成功分开计数，批次有未完成项就明确标注 `partial`。若提供批量 CLI，未完成批次应以非零退出码表示，同时保留完整成功成员的可用产物；不能只凭退出码判定验收结果。

校验单项与累计预算，记录实际中断位置；超限或未检查的成员不能算作已验证。具体字段、API、opcode 与真实游戏反例见相应引擎页。

## 独立与无副作用检查

把整个 Skill 复制到仓库外，再运行：
```text
python -B -m unittest discover -s tests -v
python -B tools/check_skill.py
```

检查不要求上游仓库、GalTransl 安装、dotnet、GUI、游戏程序或网络；叶子模块 import 不得执行批处理、读写用户文件或修改配置。

## 生成脚本不是自动完成部署

只使用有证据的方案：
- 松散文件覆盖：确认游戏确实优先读取它，以及目录/大小写/编码规则。
- 补丁归档：确认该游戏的加载顺序、名称约定和加密/filter 条件。
- 重封包：对应 writer 生成的版本必须被目标引擎读取；重新列目录、解包并核对内容。

读取多个版本不代表 writer 能生成所有版本。若索引、名称或布局参与密钥/校验计算，重建后必须同步更新；解密后得到的剧本外壳也不能假定装包时自动恢复。具体版本和算法依对应引擎页核实。

尚未确认加载规则时，交付新剧本及待验证条件，不声称“放进去就能运行”。覆盖原件、安装字体/UIF等运行时组件、启动游戏必须另获授权。

## 用户授权后的真实游戏检查

在副本中测试开场、不同说话人、旁白、选择支、跳转、存读档、多行、ruby、字体、特殊字符及长译文。记录游戏版本、样本哈希、修改项和可复现步骤。出现缺字、崩溃或分支错乱时恢复副本，不继续用更宽松的编码/截断掩盖错误。

## 报告模板

```text
引擎/方言：
识别证据与仍有的歧义：
输入副本/原件保护：
Python 参考模块、profile/边界证据与版本：
索引成员/已探测/已解码/成功脚本/正文/姓名/选项数量：
blocked / skipped / non_target / 批次 partial 及原因：
扫描 truncated / evidence_capped、实际扫描范围与预算：
原文 JSON、译文、manifest、输出位置：
原文往返：字节一致 / 结构一致（差异说明）/ 未完成
变长及控制码测试：
重封包验证：
真实样本/游戏加载：未验证 / 具体证据
尚缺的密钥、元数据、writer、字体或运行条件：
```

失败即停止发布当前成员的结果，不靠外部程序退出码判断完成；有些工具遇错仍退出 0，必须检查实际产物和结构。**停止写入不等于停止只读研究**：保留有界诊断 → 查随包实现与格式资料 → 根据游戏样本补齐算法并保留既有许可通知→ 合成正负例验证 → 新目录重试。区分缺格式证据、尚未实现、局部实现、缺 writer、许可待核；不以放宽 unknown/编码规则掩盖失败。
