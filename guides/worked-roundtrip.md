# 导出 JSON、保存 manifest 与回填新脚本

本篇规定已确认格式后的集成步骤。具体 parser、writer、定位字段和可运行格式示例放在各自的引擎页；公共层不负责从未知 bytes 找对白，也没有适用于所有引擎的统一回填函数。

前置阅读：[数据契约](roundtrip-contract.md)、[Python API](python-reference-api.md)、[编码与控制码](encoding-and-control-codes.md)。没有可靠的格式或方言证据时，先按 [识别指南](detection.md) 补齐证据。

## 1. 固定输入与解析条件

- 保存原始输入、全部配套文件及哈希；记录解密/解压前后的来源链。
- 明确引擎、方言、参考实现版本、编码、profile、预算与必要参数。回填沿用同一组条件。
- 在预算内完整解析成员；未知结构或未证明的语义阻挡该成员，不以可读字符串代替解析结果。

## 2. 导出语义与真实定位

由引擎 parser 确定正文、姓名、旁白、选项与内部字符串，按事件或文本节点顺序导出。保留重复正文与独立身份；未提供姓名结构时不凭正文猜造 `name`。

导出结果必须同时具备：

| 数据 | 来源与用途 |
|---|---|
| `rows` | 有序的翻译记录，仅含契约允许的字段 |
| `locators` | parser 给出的真实节点、指令、记录或引用身份，不按原文搜索生成 |
| `name_policies` | 每条姓名为 absent/context/writable 的证据 |
| 受保护 token | 当前语法中的控制片段及所需的顺序、嵌套和转义约束 |

完整成功但零可翻译行时只记 `empty`，不创建翻译队列文件；部分解析不算成功。

## 3. 生成 JSON 与独立 manifest

用 `make_manifest()` 记录源文件、原文摘要、定位、姓名策略与格式参数；用 `dump_rows()` 输出 UTF-8 翻译 JSON。具体调用形态见 [数据契约](roundtrip-contract.md) 中的最小集成示例。

原文 JSON 放 `gt_input/`，manifest 放 `metadata/`，回填基准及配套文件放 `original/`。文件名平铺、冲突显式消歧，来源到输出的映射写入元数据。译文回到同名 `gt_output/` 文件，不能改条数、顺序和姓名槽。

## 4. 翻译前通过原文往返

原文真实经过选定的 parser 与 writer，再重新读取结果；不能用直接复制原文件作为 writer 的验证。应先用有独立预期 bytes/offset 的人工 fixture 检查算法，再记录真实输入的往返证据。

确定性格式要求字节一致；合法的压缩或序列化规范化须列明差异，并核对解码内容、指针、引用与非文本区。编码可能存在多个原字节映射到同一字符的情况，未改记录需按引擎的保真策略保留，不以字符串相等掩盖字节变化。

未通过原文往返，不进入批量翻译。只有读能力而没有 writer 时明确交付只读阶段及缺口。

## 5. 校验译文并重建

先用 `validate_translation()` 核对来源、原文摘要、条数、字段、姓名槽、基础编码与列出的控制 token；再由适配器核对 token 顺序/嵌套、混合编码、字段容量和语法。纯数组无法自动发现等长重排，必须由翻译过程保序。

重新解析原始输入并核对 locator，按原始身份形成替换计划。实际 writer 负责长度、地址、共享引用、对齐、校验和必要外壳；公共字节替换或字符串替换不能代替这些步骤。

严格编码，不吞掉不能表示的字符，不截断超长译文。更短、同长、更长、多字节、空文本、重复文本的不同译文与坏输入都应按格式验证；不假定换一个 JSON 编码就能让游戏显示中文。

## 6. 重解析后安全发布

检查重建结果的译文、记录身份、跳转/引用和非文本数据，再用 [write_new_tree](../python/common/safety.py) 发布到新的独立输出目录。具体调用与目录前提见 [安全写出示例](python-reference-api.md#安全写出示例)。失败保留原件和上一次有效输出，不发布当前成员的半成品。

报告每个成员经过的阶段、数量、哈希、差异和未完成条件。脚本写回、外壳恢复、归档重建与游戏加载分别验收；部署条件与真实运行检查遵循 [验证与部署](validation-and-deployment.md)。
