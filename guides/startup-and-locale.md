# 启动与区域：Windows 运行环境排查

本页用于游戏在 Windows 上无法启动、黑屏或闪退时的诊断。部分依赖系统 ANSI 代码页的程序会受区域设置影响，但仅凭游戏年代、异常码或闪退现象不能确定原因。

启动验证与离线提取分开：无法运行游戏时仍可按[识别指南](detection.md)进行有界只读分析，报告游戏显示未验证。能正常运行时无需预先转区或转码。

## 先建立对照

保存错误提示、事件日志、程序版本、启动方式和当前区域信息。已有用户存档与配置先保留；需要修改时在工作副本中进行，每次只改变一个因素。部署和启动沿用主 Skill 的授权边界。

| 线索 | 下一步 |
|---|---|
| 提示缺少 DLL 或组件 | 根据发行方要求核对 DirectX、VC 运行库或其他依赖，从可信来源安装匹配版本与位数 |
| 安装失败或提示需要介质 | 检查安装完整性、镜像格式及发行方的介质要求 |
| 存档目录名、路径或配置出现乱码 | 把区域/编码列为候选，比较相同文件在原环境和日文区域环境中的表现 |
| 只有加入补丁后失败 | 在独立副本中对比原版与补丁版，核对加载顺序、编码、校验及资源完整性 |
| 固定位置崩溃或异常码 `0xC0000005` | 结合故障模块、调用位置与日志继续定位；访问冲突不是区域问题的专用标志 |

目录名乱码可以说明某条文本处理路径存在编码不匹配，不能单独证明它导致崩溃；目录名正常也不能排除脚本或其他路径的代码页问题。

## 检查非区域因素

- 核对图形、音频及输入设备的初始化日志和运行库要求；列出显卡型号不能证明运行兼容。
- 在新的 ASCII 路径副本中测试路径因素。目录联接仍指向原文件，不能充当安全工作副本。
- 若已安装补丁，保留当前副本，再用可靠原版建立对照，不直接覆盖 EXE。
- 根据程序要求测试兼容模式或合法介质。挂载前后表现相同只说明当前测试未改变结果，不能据此排除介质校验。

## 区域环境对照

确认程序依赖系统代码页后，可对兼容的 Windows **32 位程序**尝试 Locale Emulator 的日文区域配置（ja-JP）。它不支持任意 64 位程序，也不能解决所有区域或依赖问题。

1. 从项目正式发布页获取完整安装包，核对版本、依赖与程序位数；缺失 DLL 时重新核对包完整性，不从不明来源单独下载 DLL。
2. 使用该版本的配置界面建立日文区域配置，优先保持普通用户权限。配置文件位置和命令行参数以所用版本为准。
3. 在工作副本中使用相同入口、参数与工作目录启动，对比菜单、开场、存档路径及新产生的错误日志。
4. 记录实际改善的阶段；进程存活或目录名正常不能代替开场显示与存读档验证。

改系统的“非 Unicode 程序的语言”会影响其他程序，通常需要重启；更改前记录原值，并取得覆盖该操作的授权。不要为一次排查默认修改系统区域、全局 UTF-8 选项或管理员权限。

## 安装介质

MDF/MDS 不是 ISO，Windows 自带挂载不保证支持。MDS 常包含与 MDF 配套的布局信息；格式要求配对时应保留原文件名及同目录关系。

- 先确认镜像类型与完整性，再选择支持该格式的读取或挂载工具。
- 某些数据镜像可以由解包工具读取，但不能据此推断所有 MDF 都能直接提取，或提取结果满足运行时介质检查。
- 出现 `Headers Error`、CRC 错误或缺失成员时先保留诊断并核验完整性，不一概忽略。
- 安装虚拟光驱驱动、运行安装程序及启动游戏需要相应授权；不要把静默安装驱动当默认步骤。

## 日志与编码

日志可能位于程序目录、存档目录或用户数据目录，名称与编码由具体引擎决定。先查看 BOM 和有限字节样本，再严格解码；UTF-16LE、UTF-8、CP932 都可能出现，不固定使用某一个 codec。

设备初始化成功可帮助缩小已完成的阶段，但最后一条日志不一定就是故障位置。资源读取失败、索引越界等提示也可能源于缺文件、损坏或格式问题，应结合原版对照检查，不能统一归因于区域。

## 与中文回注的关系

[JIS 替换](jis-substitution.md)保留 CP932 脚本；若实际加载路径按系统 ANSI 代码页解码，仍需确认运行环境能正确读取这些字节。运行环境验证影响试注与显示结论，不阻止离线提取。

只有确认**具体脚本格式和读取路径**支持目标编码后，才可另行适配转码 writer；不要为修复启动直接把任意二进制脚本整体改为 UTF-16。BOM、长度、指针和配套文件约束见[编码指南](encoding-and-control-codes.md)。同一文本字段选择一种已验证的写入方案，并与对应的显示配置配套；不同资源的编码需分别记录。
