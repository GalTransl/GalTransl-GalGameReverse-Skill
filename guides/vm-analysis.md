# VM 分析与语义重建

用于增加或修改字节码 parser/writer；格式字段写入对应引擎页，样本分析及运行报告放结果目录。来源见[工程资料出处](../provenance/translation-engineering-notes.json)。本页规定建模和验证条件，不要求所有已有文本方言都生成 asm，也不规定必须拆成三个 Python 文件。

## 指令定义与证据

建立同一份指令定义供 reader/writer 使用。按明确版本记录 opcode/掩码、助记符、最小长度或长度公式、操作数宽度/端序/符号性、子 opcode/变体条件、栈 pop/push、作用及依据。名称优先采用已确认的 API/handler 名；语义未明的结构不能编造助记符或以空模板当完整支持。

先确认 VM 读取路径、指令/记录/段边界、表达式子语言和入口模型。静态分析读取 helper 时按函数体确认宽度和游标推进，不按地址或名字推断。switch fall-through 共用 handler，常量循环重复读取，条件分支可能选择不同参数形状；不能简单统计反编译文本中出现的读取调用数。

完整重建需覆盖可执行指令与声明数据区；样本中未命中的合法指令仍表示测试缺口。遇未知 opcode 时记录偏移、有限上下文，先回查上一条长度及变体，再查当前 handler。自描述长度可支持结构扫描，但不自动给出显示语义；未知执行范围不能靠固定长度跳过后发布成功。

## 语义视图与物理布局

文本可能内嵌、独立池存储或混合。语义编辑视图可在引用点显示字符串，但必须保留逻辑 ID、作用域和真实存储关系，不把编辑视图中的内联表示误写成内嵌字节。共享池项可用一个定义多次引用；不同上下文需不同译文时，按已证明的引用克隆池项或明确拒绝，不能按出现顺序覆盖。

选择指令若只消费字符串引用，语义层标为 TextRef 等引用角色；writer 还原原指令，不能凭空增加显示调用。姓名、资源符号、函数和文件路径分开分类，不能因为都是字符串就导出对白。外部符号保存作用域和原始表示，未解析时拒绝需要重定位的写入。

语义文本应使用能无损往返的引号、转义和控制 token 语法；真实换行、字面反斜杠、CR/LF 和不可显示字节分别表示，并处理占位符自身的转义。保护控制 token 不等于把未知字节宣布为已解析指令。不透明数据块仅在边界已证明时保留原字节，原始 dump 放诊断/metadata，不能以 dump 绕过代码覆盖检查。

## 地址、对齐与重布局

对每个引用明确：字段位置、宽度、地址空间、基址、字节/字单位、相对起点和目标身份。跳转/调用及头部、函数、标签、switch 入口统一用逻辑标签映射；range/sparse switch 和表达式里的目标也需枚举，不能只修主指令流。

汇编按布局与回填分开计算：先确定段、记录、文本、数据块和指令的新位置，再写入地址、长度、计数、索引和校验。若引用从窄字段升级成宽指令会再次改变代码布局，须计算到稳定或拒绝超限，不能一次加 delta 完成。非法/重复标签、未解析符号、目标落入操作数中、字段溢出及布局冲突均报错。

只在格式证明需要时自动对齐，不给指令流插入美观填充。已确认的固定填充可表达为对齐规则，并按新游标重算；非零或用途未明的填充保留原字节。边界未明时不能按若干字节或猜测跳转锚点切出“数据”。变长后与固定填充长度冲突须研究格式约束。

## 验证范围

原文必须经过真实解析及重建，比较字节或解释允许的规范化差异；变长后再解析、再汇编，核对引用、文本和非文本结构。独立 fixtures 覆盖共享引用、子 opcode、表达式、嵌入数据、对齐、窄引用升级和边界拒绝；不用 reader/writer 的互相一致代替独立预期。编辑生效与引用字段日志遵循[验证指南](validation-and-deployment.md#编辑生效确定性与引用字段)。

解密/解压和再加密/压缩分别验证，明文零差异不代表密文或外壳已正确恢复；确定性密码也不能保证重新压缩逐字节一致。游戏显示与选择跳转仍需另行验证。
