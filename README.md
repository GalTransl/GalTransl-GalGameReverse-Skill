# GalTransl-GalGameReverse-Skill

**想给喜欢的 Galgame 做汉化，却不知道怎么把台词提取出来、翻译后又怎么放回去？这个项目就是帮你处理这些步骤的。**

它是一份给 AI 助手使用的汉化工具包，包含游戏引擎的识别方法、解包与文本回写脚本，以及配套说明。你把工具包和游戏目录交给能够读写本地文件、运行 Python 的 AI 助手，让它分析游戏、提取台词，再根据译文制作补丁。

你不必先学会逆向或自己写脚本，可以从一段中文能否在游戏里正常显示开始。

## 它和 GalTransl 有什么关系？

汉化游戏大致分成三步：

```text
游戏文件 ──提取──→ 日文台词 ──翻译──→ 中文台词 ──回写──→ 游戏补丁
          本项目             GalTransl             本项目
```

| 工具 | 帮你做什么 |
|---|---|
| 本项目 + AI 助手 | 找出游戏里的剧情文本，导出可翻译文件；翻译后校验、回写，按引擎条件生成补丁或重封包 |
| [GalTransl](https://github.com/GalTransl/GalTransl) | 调用翻译模型，把日文台词翻成中文，并提供人名字典、校对等功能 |
| 你 | 确定人名和翻译风格、检查译文，在游戏里确认补丁效果 |

本项目可以独立使用，不需要安装 GalTransl 才能提取文本。导出的 JSON 文件兼容 GalTransl，也可以交给人工翻译或其他兼容工具处理。

**目前没有双击就能完成汉化的独立界面，也不能保证所有游戏都能处理。** 同一引擎的不同版本也可能需要适配。AI 应先确认这款游戏能提取、能回写到哪一步，再建议你开始翻译。

## 开始前准备什么？

1. **一份能正常运行的游戏。** 保留原版，后续在副本上测试补丁。
2. **一个能操作本地文件、运行脚本的 AI 助手。** 仅能聊天、无法访问游戏目录的网页对话不能直接完成这些操作。
3. **完整下载的本项目。** 在仓库页面选择 **Code → Download ZIP** 并解压，保留整个文件夹，不要只下载 `SKILL.md`。
4. **Python 3.11 或更新版本。** 随包核心脚本使用标准库；你可以先让 AI 检查环境，特定格式有额外要求时再处理。
5. **翻译工具。** 推荐使用 [GalTransl 桌面版](https://github.com/GalTransl/GalTransl/releases)。翻译服务的配置与费用取决于你选择的模型，详见 [GalTransl 使用说明](https://github.com/GalTransl/GalTransl#环境准备)。

这里的 **Skill** 可以理解为“给 AI 的操作手册和工具箱”。第一次使用不用研究安装规则，**把本git网址或下载的本地目录发给他，让 AI 直接安装这个skill，或者直接不安装，使用时把本地目录发给AI即可。**

## 跟着做：先让开场的几句台词变成中文

### 第一步：让 AI 分析游戏并提取台词

把下面这段话发给 AI，将两个方括号里的内容换成你的实际路径：

```text
请使用 GalTransl-GalGameReverse-Skill，帮我提取剧情文本： [游戏文件夹路径]。
```

你不需要提前知道游戏使用什么引擎，也不用自己从一堆资源包里找剧本。

正常情况下，AI 会在游戏目录里新建一个结果文件夹，结构大致如下。如果已有同名目录，它会换一个新名字，保留之前的结果。

```text
游戏目录/
└─ 游戏名_extract/
   ├─ gt_input/     ← 提取出的原文，导入 GalTransl
   ├─ gt_output/    ← 翻译完成后，把同名译文放到这里
   ├─ original/     ← 回写时需要的原始脚本，保留不动
   ├─ metadata/     ← 原文与游戏脚本的对应信息，保留不动
   └─ reports/      ← 提取结果、检查记录和未解决的问题
```

**你主要用到 `gt_input` 和 `gt_output`，但请保留整个结果文件夹。** 只有译文、没有原始脚本和对应信息，AI 就无法可靠地把文字放回正确的位置。

提取结束后，AI 应给你一张结果表，说明剧情来自哪些文件、用了什么编码、提取了多少脚本和台词，以及回写是否通过检查。“提取成功”还不代表补丁已经能在游戏里使用。

### 第二步：先试几句中文

先别急着翻译整部游戏。花一点时间确认中文能正常显示，可以避免翻完几十万字才发现回写或字体有问题。

让 AI 选择一个容易在游戏里看到的剧情文件，通常是开场，并发给它：

```text
请把推荐的开场文件按同名复制到 gt_output，只将前几句正文改成简短的中文测试句。
保留其他内容和顺序，不修改 gt_input，也不要覆盖已有译文。
请校验、回写并生成测试补丁，告诉我怎么在游戏副本中测试。
```

默认由 AI 执行回写和打包。你按它针对这款游戏给出的说明放置补丁，启动游戏检查：

- 测试的中文有没有出现，姓名和对白是否对应。
- 有没有乱码、方框、缺字或文字超出对话框。
- 能不能继续对话、进入选项，有没有崩溃或卡住。

如果出现问题，把出问题的位置和现象告诉 AI，必要时附上截图。有些日文引擎还需要字体或字符替换配置，这些应先在小规模测试中解决。AI 生成了补丁但没有实际运行游戏时，应明确说明“游戏显示未验证”。

### 第三步：用 GalTransl 翻译

测试通过后，就可以开始正式翻译了：

1. 在 GalTransl 中新建项目，导入本次提取目录 `gt_input` 中的 JSON 文件。
2. 配置翻译模型，至少先设置主要角色的人名字典，避免同一个人被翻成几个名字。
3. 开始翻译，完成后检查译文与自动找错结果；需要修正时，按 GalTransl 的说明重新生成最终译文文件。
4. 将**最终译文 JSON** 按原文件名放回本次提取目录的 `gt_output`，不要把翻译缓存当作回写文件。

文件应直接放在 `gt_output` 里，不额外套一层子目录。例如，原文是 `gt_input/start.json`，译文就应是 `gt_output/start.json`。这里的文件名只是示意，以实际导出名称为准。

不要增删或重排台词条目，也不要随意删除文本中的特殊标记。它们可能控制换行、等待或变量显示。人工校对时同样需要保留这些结构。

### 第四步：让 AI 回写正式译文

译文准备好后，在原来的对话里告诉 AI：

```text
译文已按同名文件放回这次提取目录的 gt_output。
请校验译文，回写游戏脚本并生成补丁或重封包，输出到新目录。
告诉我生成了哪些文件、如何在游戏副本中使用，以及还有哪些内容需要实测。
```

之后由 AI 处理文件对应、文本回写与打包，你继续检查游戏里的实际效果。开场显示正常只是第一步，正式补丁还需要检查各条路线、选项、姓名和长句排版。

## 常见问题

### 我的游戏在支持范围内吗？

最直接的办法是让 AI 读取 `SKILL.md` 并分析游戏目录。[引擎索引](SKILL.md#引擎索引)可以查看已有资料，但**列出引擎不等于它的所有游戏都支持完整汉化**：有的已经具备提取和回写能力，有的只实现了解包或部分脚本处理。

遇到暂未支持的版本，AI 可以结合随包资料和游戏样本继续分析、补充适配；能否完成取决于具体格式，不能靠文件扩展名相同就直接套用。

### 解包、提取、回写、封包到底有什么区别？

| 步骤 | 可以这样理解 |
|---|---|
| 解包 | 打开游戏的资源包，取出其中的文件 |
| 提取 | 从剧情脚本中找出台词、姓名和选项，整理成可翻译文件 |
| 回写 / 回填 / 注入 | 把译文放回剧情脚本，同时保持游戏指令和文件结构正确 |
| 封包 | 把修改后的脚本装回资源包；部分引擎可以直接加载单独的补丁文件 |

每一步都可能有不同的格式要求。所以“解包工具能打开”与“已经能做汉化补丁”之间，还有提取、回写和显示验证要完成。

### 会修改我的原游戏吗？

默认只在游戏目录里新建结果文件夹，不改动原有文件。覆盖游戏文件、安装运行时补丁或让 AI 启动游戏，需要你的明确授权。建议始终在游戏副本上测试。

### 不小心直接改了 gt_input 怎么办？

先别删除文件，也别重新提取覆盖它。告诉 AI 原文被误改，让它先把修改保存到 `gt_output`，再从可靠的原始数据恢复输入。不要自己修改 `metadata` 里的校验信息来强行通过检查。

### 能把图片里的字、菜单和整个界面一起汉化吗？

本项目主要处理剧情脚本里的文字。图片上的字、程序内置菜单和特殊界面可能不在剧情脚本里，需要另外定位和处理。提取报告应说明实际覆盖范围，不能把导出的台词当作游戏的全部文字。

<summary>安装为 Skill、代码组织与开发检查</summary>

支持 `SKILL.md` 的 AI 工具可以按各自规则安装本项目。请复制完整目录，安装目录名使用 `galtransl-galgamereverse-skill`。是否自动发现取决于宿主；无法自动发现时，直接让 AI 阅读 `SKILL.md` 即可。

代码按用途组织：

- `python/archives/`：资源包索引、解包与封包。
- `python/engines/`：剧情脚本解析、文本提取与回写。
- `python/common/`：共享校验、安全输出与编码处理。
- `tests/`：人工构造样例与回归测试。
- `catalog/`：格式与来源线索，不是完整支持列表。

本项目没有统一的批量汉化命令。AI 应按对应引擎页选择接口，必要时编写适配脚本；所需参考资料与算法随包提供，不要求用户另外下载上游源码。

在项目根目录运行开发检查：

```text
python -B -m unittest discover -s tests -v
python -B tools/check_skill.py
```

合成测试通过不等于真实游戏验证通过。处理游戏时，应分别记录解包、文本提取、原文回写、中文回写、封包与实际显示的状态；具体运行记录留在游戏结果目录的 `reports/`，不收入仓库。
